# A–House

[Открыть прототип](https://anton-gorokhovatsky.github.io/a-house/) · [Действующий сайт A–House](https://ahouseproject.com/)

Статическая версия основного сайта для совместной работы с командой. В ней 26 страниц из основной карты сайта и 62 публикации из двух архивных лент. У публикаций сохранены адреса /tpost/ и появился [общий архив](https://anton-gorokhovatsky.github.io/a-house/archive/). Самостоятельные проекты A–News, A–Index, фестиваль и сервис регистрации открываются на своих сайтах.

При проектировании и перед каждым релизом всего сайта действуют [правила A–House](AGENTS.md). Применение справочника Бирмана к страницам, маршрутам и формам разобрано в [проектном руководстве](docs/interface-design.md).

## Что можно посмотреть

- На [главной](https://anton-gorokhovatsky.github.io/a-house/) можно найти событие, познакомиться с проектами, почитать журналы и узнать о клубе. Ссылка «Об A–House» открывает [рассказ о платформе и её патронах](https://anton-gorokhovatsky.github.io/a-house/about/).
- [Календарь](https://anton-gorokhovatsky.github.io/a-house/calendar/) объединяет ближайшие и прошедшие события. Сохраняются ссылки на месяцы, на каждую встречу и на [семейную программу](https://anton-gorokhovatsky.github.io/a-house/calendar/?audience=kids).
- В [разделе вакансий](https://anton-gorokhovatsky.github.io/a-house/#jobs) кандидат видит открытые позиции, раскрывает условия и может откликнуться на конкретную должность на hh.ru.
- [Клуб](https://anton-gorokhovatsky.github.io/a-house/club/) — условия трёх уровней участия, фотографии и переход в анкету с выбранным уровнем.
- [Бизнес Москвы](https://anton-gorokhovatsky.github.io/a-house/moscow_business/) — пять карточек программы, материалы встреч и архив из десяти записей.
- [Годовой отчёт](https://anton-gorokhovatsky.github.io/a-house/report/) — раскрывающиеся разделы и фотоматериалы. В старых публикациях работают фотогалереи и возврат в архив.

[Заказ A–Friend](https://anton-gorokhovatsky.github.io/a-house/#a-friend) открывается из карточки издания. Рядом с ценой подписки посетитель заполняет имя и фамилию, почту и телефон. [Анкета клуба](https://anton-gorokhovatsky.github.io/a-house/member/) принимает заявки на три программы. При переходе со страницы клуба в анкете уже выбрана соответствующая программа. Пока у продукта отсутствуют подтверждённые условия и адрес приёма, посетитель видит это до полей и отправка закрыта.

Пропуск A–PASS пока можно посмотреть в демонстрационной форме. Ссылки на Timepad, документы и самостоятельные проекты ведут по опубликованным адресам. Для отсутствующих материалов есть страница 404 с выходом на главную и в архив.

При первом посещении сайт следует светлой или тёмной теме устройства. На телефоне тему можно сменить прямо в открытом меню и продолжить читать с того же места. Тот же выбор доступен в подвале перед документами и реквизитами. Ручной выбор сохраняется в этом браузере. Режим «Как в системе» снова включает переключение вместе с устройством. Фотографии, печатные обложки и авторские плакаты сохраняют исходные цвета.

## Как запустить

Понадобится Node.js 20 или новее. Установка пакетов для сборки не нужна.

~~~sh
npm run dev
~~~

Локальная версия открывается на [localhost:4173/a-house/](http://localhost:4173/a-house/). После правки исходников выполните npm run build и обновите вкладку. Для сборки под корень своего домена задайте SITE_BASE=/ при запуске.

Для проверки релиза нужны Google Chrome и WebKit той версии, которую устанавливает Playwright из `package-lock.json`. GitHub Actions выполняет обе браузерные проверки перед публикацией из `main`.

В футере каждой страницы указаны дата и московское время редакции сайта. Сборка берёт время коммита из `git show -s --format=%cI HEAD`. Новая редакция получает свою дату, в том числе при нескольких выпусках за день. Повторная публикация того же коммита сохраняет подпись. Для локальной копии без сведений Git выводится «Локальная сборка».

~~~sh
npm ci --ignore-scripts
node_modules/.bin/playwright-core install webkit
npm run build
npm run check
npm run check:browser
npm run check:browser:webkit
~~~

GitHub Pages получает только содержимое `dist/`. У тестового сайта и его страницы 404 в исходном HTML есть robots noindex. Ссылкой можно делиться, авторизация для просмотра не нужна.

`npm run check` проходит по внутренним ссылкам от главной и проверяет страницы назначения и якоря. WebKit проверяет мобильный сценарий в профиле iPhone 13 и клавиатурный сценарий на широком экране. В обоих движках проверяются старые ссылки, раскрытия, диалоги и возврат фокуса на спецстраницах.

Шесть спецстраниц сохраняют собственные композиции. Их разметка находится в `src/pages/`, стили — в `src/styles/pages/`. `src/js/feature-controls.js` обслуживает раскрытия, диалоги и галереи. Прежние фрагменты адресов записаны в `data-fragments`, чтобы опубликованные ссылки продолжали открывать нужные материалы. Шрифты и изображения отдаются с сайта.

## Где редактировать

| Что меняем | Где это находится |
| --- | --- |
| Текст или фотографии раздела | HTML соответствующего раздела в src/pages/. Редакционные публикации лежат в src/pages/tpost/. В src/routes.json указаны заголовок страницы, адрес и её стили. |
| Меню и общие контакты | `src/partials/editorial-header.html` и `home-footer.html` задают шапку и подвал главной, клуба и анкеты. Прочие страницы используют `header.html` и `footer.html`. Общие адреса и документы берутся из `footer.html`. |
| Оформление | Общие правила в src/styles/site.css, локальные стили страниц в src/styles/pages/. Исходная сетка и числовые идентификаторы сохранены для совпадения с авторскими макетами. |
| Поведение | `src/js/site.js` управляет сеткой, меню и архивом. `src/js/interactions.js` отвечает за галереи и раскрытия. Заказ A–Friend и клубная заявка используют `src/js/membership.js`, прежние сервисные страницы — `src/js/services.js`. |
| Фотографии и шрифты | media/. Роли фирменных гарнитур, открытые шрифты и их происхождение описаны в [инструкции к шрифтам](media/fonts/README.md). |

HTML, JavaScript, стили, фотографии и шрифты приходят с того же хостинга. На странице «Об A–House» фильм загружается с YouTube при появлении в поле зрения и начинает играть без звука. При сокращённом движении, экономии трафика или просмотре архивных публикаций плеер загружается по нажатию. Для работы прототипа не нужны аккаунт Tilda, её скрипты, CDN или сервер форм.

### Как подключить приём заказов и заявок

Каждая форма подключается отдельно через переменные сборки в GitHub Actions. В них указывают общедоступные HTTPS-адреса и утверждённый текст. Секреты платёжного сервиса хранятся у обработчика.

| Для какой формы | Что задать |
| --- | --- |
| A–Friend | `A_FRIEND_ORDER_URL`, `A_FRIEND_PERIOD` (формулировка периода рядом с ценой), `A_FRIEND_TERMS_URL`, `A_FRIEND_CONSENT_URL`, `A_FRIEND_CONSENT_TEXT` |
| Клуб | `A_MEMBER_APPLICATION_URL`, `A_MEMBER_TERMS_URL`, `A_MEMBER_CONSENT_URL`, `A_MEMBER_CONSENT_TEXT` |

После подключения обработчика браузер отправляет POST с типом `application/x-www-form-urlencoded`. Заказ A–Friend передаёт `product=A-Friend`, `quantity`, `name`, `email`, `phone`, необязательные `workarea` и `comment`, а также `consent=1`. Поле `comment` подходит и для имени получателя подарка. Клуб получает `offer` (`member`, `patron` или `platinum`), `name`, `company`, `phone`, `email`, `connect` и `consent`. Дополнительные поля анкеты клуба — `sphere`, `profession`, `recommendations`, `comment`.

Обработчик заказа сверяет продукт и цену со своим каталогом, создаёт заказ и открывает оплату. Доступ в приложении выдаётся по подтверждению платежа. Перед подключением проверить с тестовой кассой отмену, повтор и возврат.

### Как заявка клуба попадает в почту

`node server/member-application.mjs` запускает обработчик `POST /application` на `127.0.0.1:8787`. Его HTTPS-адрес указывается в `A_MEMBER_APPLICATION_URL` для сборки сайта. Переменные обработчика задаются на его сервере.

| Переменная | Значение |
| --- | --- |
| `A_MEMBER_SITE_URL` | Полный адрес сайта с завершающей косой чертой. Определяет допустимый источник заявки и адрес возврата к программам. |
| `A_MEMBER_CONSENT_URL` | Тот же адрес текста согласия, что указан в сборке сайта. Письмо содержит эту ссылку и время отправки анкеты. |
| `A_MEMBER_SMTP_URL` | Адрес почтового сервера `smtps://` или `smtp://` с STARTTLS. Учётные данные задаются только на сервере. |
| `A_MEMBER_MAIL_FROM`, `A_MEMBER_MAIL_TO` | Адрес отправителя в почтовом сервисе и адрес получателя заявок. |

В письме видны выбранная программа, имя, контакты, способ связи и заполненные дополнительные поля. Обычный ответ на письмо адресуется заявителю. Обработчик возвращает подтверждение после приёма письма почтовым сервером. Ошибка сохраняет введённое в анкете и позволяет повторить отправку. Если используется другой обработчик, на запрос с заголовком `Accept: application/json` он возвращает `200` и `{"status":"accepted"}` только после подтверждённого приёма и разрешает запрос с адреса сайта через CORS. Для обычной отправки без JavaScript доступна HTML-страница с результатом.
