# Кабинет финала на GitHub Pages

GitHub Pages отдаёт интерфейс кабинета. Supabase проверяет логины, выдаёт каталог и PDF только аккаунтам из списка жюри. Вход выполняется напрямую через HTTPS API Supabase. Сеанс хранится в открытой вкладке. После перезагрузки страницы понадобится войти снова.

## Настройка Supabase

1. Создайте отдельный проект для финала. Отключите свободную регистрацию и анонимный вход. Укажите URL кабинета в настройках Auth.
2. Выполните `schema.sql` в этом проекте. Политики допуска сравнивают идентификатор входящего пользователя со списком жюри. Каталог и PDF доступны только на чтение.
3. Запустите `provision.mjs` с двумя путями. Первый указывает на закрытую папку с ответами Supabase CLI `project.json` и `api-keys.json` для выделенного проекта `a-house-mts-jury`. Во втором лежит каталог, подготовленный `import-materials.py`.

```sh
node jury/final/hosted/provision.mjs /private/contest/setup /private/contest/final
```

Скрипт создаёт 15 индивидуальных учёток и закрытый бакет. После проверки допуска он сохраняет `public-config.json` для сборки и `jury-access.tsv` для организатора. Файлы с доступами и PDF хранятся в закрытых папках.

## Голосование в финале

После создания учёток один раз примените `voting.sql` к проекту финала. Семь логинов `jury-01` – `jury-07` соответствуют строкам утверждённого состава в пункте 2.3. Номер 03 закреплён за Виктором Беловым, представителем технического блока МТС. Учётки 08–15 открывают материалы с правом просмотра. Укажите ссылку на полное положение в `jury_final_control.regulations_url`, чтобы она открывалась из личного кабинета.

В каждой работе доступны оценки от 0 до 5 и комментарий. Для интеграции в ландшафт можно указать, что место размещения не определено. Веса и права на технические критерии задаёт таблица `jury_final_criteria`. Эксперт может изменить собственную оценку. Форма помечает её сохранённой после подтверждения сервера. Приём открыт с момента установки. Куратор может закрыть его командой `update public.jury_final_control set accepting = false where singleton`. Сохранённые листы остаются доступны для чтения.

В SQL Editor организатор может открыть листы в `public.jury_final_ballots` и рабочую сводку `select * from public.jury_final_work_summary order by position`. Сводка усредняет баллы отдельно по каждому критерию, затем применяет веса. Рабочий балл появляется при наличии четырёх листов за эту работу и технической оценки. При подведении итогов куратор проверяет представление листов в срок и кворум всего этапа. При средней реализуемости ниже 4 работа исключается из претендентов на приз и реализацию, ниже 2 также исключается из рекомендаций к выставке. Решения оформляются протоколом жюри.

## Сборка и проверка

Укажите URL проекта и его публичный ключ `sb_publishable_…` в переменных окружения.

```sh
export JURY_SUPABASE_URL=https://PROJECT_REF.supabase.co
export JURY_SUPABASE_PUBLISHABLE_KEY=sb_publishable_EXAMPLE
node jury/final/hosted/build.mjs /tmp/a-house-jury-site
```

Публикуйте только файлы сборки. Браузерная проверка проходит путь от входа до PDF и обратно в эмуляции iPhone 13 и в Chrome.

```sh
node jury/final/hosted/check.mjs https://YOUR_PAGES_URL/ /private/contest/setup /private/contest/final
```
